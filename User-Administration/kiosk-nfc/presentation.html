Approche initiale

Point de départ : NFC + Active Directory

Une solution simple, rapide et ergonomique basée sur deux facteurs :

Facteur 1 — Possession

Badge NFC (Mifare) déjà attribué → aucune nouvelle carte à émettre

Facteur 2 — Connaissance (Code PIN)

Code PIN localisé à 6 ou 8 chiffres, évitant l'usage du vrai mot de passe AD

Principe : Réutiliser l'existant (badge bâtiment + AD) pour créer une MFA légère, sans surcoût matériel.

Technique

Stack technique — Nexorsys NFC Kiosque

.NET 8 WPF

Client lourd natif. Architecture MVVM. Aucun runtime navigateur vulnérable.

NFC / PCSC

Dialogue bas niveau via PC/SC (APDU FF CA 00 00 00). Compatible lecteurs HID / ACS.

LDAP / Active Directory

Interrogation LDAPS (port 636) via TLS. Bind sécurisé avec compte de service.

AES-256

Chiffrement des secrets locaux lié à l'empreinte machine. IV dynamique anti-replay.

Logs JSONL

Journalisation structurée asynchrone, horodatée ISO 8601. Prête pour SIEM.

Groupes AD restreints

Accès conditionné à l'appartenance à un groupe AD dédié. Rejet catégorique sinon.

⚠ Contraintes terrain

Réalités du déploiement hospitalier

Ces contraintes sont non-négociables et doivent guider toute décision d'authentification :

Pas de mobile pour tous

Les mobiles professionnels ne sont pas attribués à l'ensemble du personnel soignant.

Budget limité

L'acquisition d'un token physique par agent représente un investissement non budgété.

Ports USB désactivés

Politique SSI de l'établissement : les ports USB sont bloqués par GPO. Seuls les lecteurs NFC approuvés sont autorisés.

CPS réservée aux médecins

La Carte de Professionnel de Santé (CPS / e-CPS) n'est pas disponible pour les IDE et le personnel paramédical.

Risque de perte / mauvais usage

Un badge NFC peut être perdu, prêté ou cloné. Ce risque doit être encadré par une procédure.

Diversité des profils

IDE, AS, administratifs, médecins : chaque profil a des contraintes et équipements différents.

Positionnement NFC

NFC : un complément, pas un remplacement

✅ Ce que NFC apporte

Amélioration de l'ergonomie — Connexion fluide en moins de 5 secondes sur poste partagé.

Couche d'identification rapide — Le badge identifie l'agent, le Code PIN vient confirmer la présence physique sans exposer de mot de passe complexe.

Mécanisme contrôlé — Accès conditionné à un groupe AD restreint + journalisation.

Complémentaire à l'existant — S'intègre sans remplacer l'AD ou les solutions conformes.

❌ Ce que NFC n'est pas

Non conforme en standalone — Ne remplace pas CPS, e-CPS ou FIDO2 pour l'accès DMP/HDS.

Non recommandé pour accès DMP — Le niveau d'assurance du badge Mifare est insuffisant seul.

Non universel — Nécessite un lecteur NFC approuvé et un badge préalablement enregistré.

Proposition

Usage contrôlé et encadré du NFC

Identification (pas authentification seule)

L'Active Directory fournit l'identité rattachée au NFC. L'accès est conditionné par un Code PIN local (6/8 ch.).

Périmètre restreint

Limité aux postes partagés non critiques (soins généraux, logistique, accueil).

Monitoring des logs

Toutes les authentifications sont journalisées et peuvent être intégrées au SIEM.

Périmètre d'application proposé :
NFC utilisé sur les postes partagés pour les applications à criticité modérée nécessitant une traçabilité nominative sans accès DMP direct.
Bénéfice immédiat :
Un agent hospitalier s'identifie en posant son badge → gain de temps, traçabilité assurée, sessions anonymes éliminées.
  • Procédure de signalement en cas de perte de badge
  • Révocation immédiate dans l'AD
  • Rotation des badges recommandée tous les 2 ans

Sécurisation et Maîtrise

Comment le Code PIN sécurise l'environnement

Les limites inhérentes au NFC sont totalement neutralisées par la conception de la solution :

Mot de passe AD masqué

Puisque l'agent saisit un Code PIN (6 ou 8 chiffres) et non son mot de passe central complet, les regards indiscrets ne compromettent pas l'identité centrale Active Directory de l'établissement.

Risque de clonage neutralisé

Un badge physique perdu, prêté, ou volé est entièrement inutile et inexploitable s'il n'est pas accompagné du Code PIN numérique connu seul de l'agent soignant.

Contrôle Central & Réactivité

Le badge reste couplé à la base Active Directory : en cas de départ d'un collaborateur, la suspension AD désactive instantanément ses droits NFC.

Bilan : La combinaison du confort NFC avec l'exigence d'un Code PIN transforme une simple lecture de badge en un processus fort, réduisant significativement la surface d'attaque en salle de soins.
Recommandation

Recommandation DSI

❌ Ne pas faire

  • Remplacer les solutions conformes existantes (CPS, e-CPS)
  • Déployer NFC sans encadrement DSI
  • Utiliser NFC comme seul facteur d'authentification
  • Étendre à des accès DMP/HDS sans validation ANS

✅ Faire

  • Intégrer NFC comme couche complémentaire sur postes partagés
  • Utiliser un Code PIN local (6/8 ch.) comme secret d'authentification rapide
  • Restreindre via groupe AD + journalisation
  • Piloter sur un service avant généralisation

Intégrer NFC

comme couche complémentaire dans un modèle d'authentification hybride et gradué
