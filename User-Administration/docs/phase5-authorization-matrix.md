# NexorSys Identity + Kiosk — Phase 5 Authorization Matrix

This is a source-reviewed endpoint inventory for the current API, not a claim that every product capability exists. Resource lookups and mutations must derive organization scope from authenticated claims or a validated workstation certificate; caller-provided tenant, user, host, and resource identifiers are selectors only and never authorization proof.

## Endpoint inventory gaps / absent product capabilities

Kiosk security status is tenant/admin scoped and now projects credential enrollment as `HasBadge`; it never returns the raw badge UID. This supports status display and badge-management decisions without exposing a reusable authentication identifier in the API response.

The codebase currently defines no complete route families for groups, role/permission administration, site selection, MFA/FIDO2 lifecycle, emergency access, application assignment management, or customer directory configuration. Their entities or UI references do not imply an implemented authorization surface. These are product gaps, not silently treated as protected features. A full generated OpenAPI-to-policy inventory and exhaustive A→B tests for every mutation are still required before the authorization gate can pass.

The generated `docs/api-route-inventory.json` enumerates routeable controller actions (excluding MVC `[NonAction]` methods), route/action attributes, framework `[AllowAnonymous]` metadata, and declared authentication filters including Agent mTLS. It is an inventory aid, not evidence of resource-level tenant authorization.

## Security test evidence and limits

The security tests exercise selected tenant isolation across user/device/policy/audit/workstation/application-trust surfaces, attempted foreign-tenant device creation/mutation, forced tenant ownership when creating policy records, workstation/session ownership, signed license tampering/revocation/limits, executable path/hash/publisher policy, Agent IPC trust, tenant-scoped SignalR group derivation, audit redaction, and route retirement. A new Agent mTLS action filter protects the entire Agent controller; tests assert that every currently anonymous HTTP route is explicitly allowlisted and the Agent filter is attached at controller scope. PostgreSQL tests use the disposable integration database in `scripts/test-all.ps1`. This suite is still not an exhaustive per-endpoint matrix covering every resource/action and inactive/revoked/expired combination; do not interpret the current test count as closing that gap.
